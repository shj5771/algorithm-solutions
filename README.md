# algorithm-solutions

프로그래머스 / 백준 문제 풀이 기록.

## 어떻게 돌아가는가

```
프로그래머스에서 문제 통과
   ↓  백준허브 크롬 확장 (자동)
이 레포에 커밋 (원격으로 바로 푸시된다 — 로컬은 git pull 필요)
   ↓  /algo-post (스케줄 or 수동)
drafts/ 에 초안 마크다운 생성  ← GitHub에서 그대로 읽고 고칠 수 있다
   ↓  bin/copy-draft.sh
마크다운 → 스마트에디터용 HTML → 클립보드 (HTML + 평문 두 플레이버)
   ↓
붙여넣고 코드블록 채우고 발행
```

초안은 **마크다운**이다. 붙여넣기용 HTML 변환은 `bin/md-to-naver.mjs` 가 그때그때 한다.
초안 자체를 HTML로 두면 GitHub에서 태그만 보여 검토가 불가능해진다.

### RTF를 쓰지 않는 이유

처음엔 `textutil` 로 RTF를 만들어 클립보드에 올렸는데, **다크모드일 때 RTF 색상표에
흰 글자색이 박혀서** 네이버에 붙이면 흰 글자 / 검은 배경으로 나왔다.

```
{\colortbl \red255\green255\blue255 ...   <- 다크모드가 만든 흰색
```

그래서 RTF를 버리고 AppleScript로 **HTML 플레이버(`«class HTML»`)** 를 직접 올린다.
HTML에는 색을 싣지 않으므로 에디터가 자기 스타일을 적용한다. 평문도 같이 올려서
HTML을 못 받는 곳에 붙일 때 대비한다.

발행 버튼만 사람이 누른다. 네이버는 2020년 5월 글쓰기 API를 종료했고 약관상
매크로를 제재 대상으로 두기 때문에, 자동화는 초안 생성까지만 한다.

## 디렉터리

| 경로 | 용도 | 누가 쓰는가 |
|---|---|---|
| `프로그래머스/`, `백준/` | 풀이 코드 | 백준허브 (자동) — **손으로 건드리지 않는다** |
| `drafts/` | 블로그 초안 | `/algo-post` |
| `bin/` | 클립보드 복사 헬퍼 | 사람 |

백준허브가 만드는 폴더 구조는 `사이트 - 레벨 - 문제번호.문제명` 이다.
이 규칙에 맞춰 초안 생성기가 새 풀이를 찾는다.

## 사용법

```bash
git pull                     # 백준허브가 원격에 푸시한 새 풀이 받기

/algo-post                   # 초안이 없는 새 풀이들로 초안 생성

# 붙여넣기 (2단계)
bin/copy-draft.sh drafts/2026-07-28-programmers-178870.md          # 본문 (서식 유지)
bin/copy-draft.sh drafts/2026-07-28-programmers-178870.md --code   # 코드 (평문)
```

본문을 먼저 붙여넣고, 본문의 `[코드블록 1]` 자리에 스마트에디터 코드블록 컴포넌트를
만들어 `--code` 로 복사한 내용을 넣는다.

## 초안을 다시 만들고 싶을 때

`drafts/.processed.json` 에서 해당 문제 키를 지우고 `/algo-post` 를 다시 돌린다.
